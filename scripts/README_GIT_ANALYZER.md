# Git提交分析和开发准则生成器

## 概述

此脚本分析您的Git提交历史，识别常见的错误模式和改进点，然后生成一个个性化的“开发准则”文件。这个准则旨在帮助您在未来的编工作中避免重复犯同样的错误，并持续改进编码实践。

## 工作原理

1. **提交历史分析**：读取最近N次Git提交（默认10次）
2. **模式识别**：分析提交消息质量、文件变更模式、错误修复趋势等
3. **问题归类**：将发现的问题分类为提交消息问题、文件变更问题、潜在错误和工作流问题
4. **准则生成**：基于分析结果生成个性化的开发准则文件
5. **建议使用**：在开始新的编码工作前阅读此准则，以减少重复犯同样的错误

## 使用方法

### 基本使用
```bash
# 运行分析并生成开发准则
python3 scripts/git_commit_analyzer.py
```

### 自定义提交数量
虽然当前版本固定分析最近10次提交，但您可以轻松修改脚本中的参数来分析更多或更少的提交。

### 查看生成的准则
```bash
# 查看开发准则
cat DEVELOPMENT_GUIDELINES.md

# 使用分页器查看（推荐）
less DEVELOPMENT_GUIDELINES.md
```

## 准则内容说明

生成的`DEVELOPMENT_GUIDELINES.md`文件包含以下主要部分：

### 1. 提交消息规范
- 基于您提交历史中发现的问题（如消息过于模糊）
- 提供约定式提交格式的建议
- 列出应避免的泛泛而谈表达和良好示例

### 2. 从错误中学习
- 基于您过去的错误修复提交
- 建议在修复错误后思考预防措施
- 鼓励添加测试、断言或代码注释来防止类似问题

### 3. 通用编码最佳实践
- 代码质量建议（函数大小、文件大小、命名等）
- 测试意识（TDD理念、回归测试等）
- 审查与反馈建议（自审查、静态分析、他人审查等）

## 建议的使用频率

为了使开发准则保持与时俱进，建议：

1. **每周运行一次**：捕捉最近的编码模式和问题
2. **重要里程碑前后运行**：在大型功能开发前后检查是否偏离准则
3. **团队分享**：如果在团队中工作，可以考虑分享个人准则的见解
4. **与代码审查结合**：在代码审查时参考准则中的相关条目

## 故障排除

### 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 无法获取Git历史 | 不在Git仓库中或权限问题 | 确保在正确的Git仓库目录中运行脚本 |
| 中文乱码 | 编码问题 | 脚本已指定UTF-8编码，一般不会出现问题 |
| 准则生成为空 | 提交历史异常 | 检查Git历史是否正常，尝试减少分析的提交数量 |
| 权限错误 | 文件写入权限问题 | 确保有权限在目标目录写入文件 |

### 查看详细错误信息
如果脚本执行失败，可以尝试：
```bash

python3 -u scripts/git_commit_analyzer.py 2>&1
```
